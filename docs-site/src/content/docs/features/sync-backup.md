# 🔄 同步与备份目标

同步能力把项目封装产物推送到**用户自有的**三种目标之一（GitHub 私有仓 / WebDAV 远端 / 本地文件夹），再把远端同一清单拉回本地；双改文件不自动覆盖，一律逐项裁决。本页讲「产物怎么送到远端、双改怎么处理、提取预算与正史规则怎么被保护」；项目级 zip 封装、校验与恢复见 [备份与导出](/niko-buddy/features/backup-export/)；凭据与全局偏好见 [设置](/niko-buddy/features/settings/)；安装见 [下载安装](/niko-buddy/download/)。

## 主路径

- 在「设置 → 云端备份 / 同步」里选择传输目标（三种之一），填写该目标必填项，点「测试连接」确认可达
- 打开「启用同步（全局开关）」——**默认关闭**，未显式开启前后台调度器不会启动
- 选择后台同步间隔（只提供 15 / 30 / 60 分钟三档），或直接点「立即同步」手动跑一次
- 推送完成后在「批次记录」里逐批核对结果；出现双改文件时展开该批次逐项选择裁决
- 需要批量补记忆时，从章节树进入「批量提取」，在预算上限内选择范围

## 三种传输目标

目标由配置里的 `endpoint` 字面量选型，三种字面量与 Rust 侧 `sync_target.rs` 同源：

| 目标 | `endpoint` | 必填块 | 凭据 | 传输方式 |
|------|-----------|--------|------|----------|
| 本地文件夹 | `local` | `localPath`（绝对路径） | **不需要**（`credential_ref` 必须为空串） | 直接文件拷贝，目标目录在首次推送时自动创建 |
| GitHub 私有仓 | `github` | `owner` / `repo` / `branch` / `pathPrefix` | `nb:github:<account>` | ≤ 1 MiB 走 contents API 单 PUT（带 sha 并发保护）；> 1 MiB 走 Git Data API（blob → tree → commit → ref） |
| WebDAV 远端 | 端点 URL | `root`（远端根前缀） | `nb:webdav:<project_id>` | 远端 HTTP |

凭据只以**句柄**形态（`nb:<domain>:<account>`）出现在配置里，明文进系统钥匙串；落盘配置文件 `.niko-buddy/sync-config.json` 不含口令。因此配置可以随项目走、跨设备重建，而不泄露凭据。

## 全局开关与后台调度

- `enabled`（=`sync_enabled`）是**全局**同步开关，不是单个目标的启用位：关闭时后台调度器与一切自动触发全停，只保留手动入口。默认值为 `false`，且只有显式 `true` 才算开启（读不出来 = 关闭）。
- 间隔档位是契约：只接受 15 / 30 / 60 分钟，越界档位在配置期直接拒收。
- 「立即同步」与后台调度走**同一条**周期路径（`sync_now` = 调度器的 `run_cycle`），所以「开关关闭 / 未配置 / 无产物」的判定不会在手动与自动之间漂移。
- 一次周期「没跑」不是异常：`skip_reason` 会说明原因（`disabled` / `not_configured` / `window_closed` / `sleeping` / `offline` / `no_artifact`），面板原样显示。

## 批次明细查看

每次推送或拉取在传输 journal（`.novel/sync-journal.jsonl`）落一行，一个批次 = `manifest_id` + `revision` + `direction` + `ts` + `device_id`。「批次记录」区按批列出：

- 批次行：清单号 · 版本 · 方向 · 状态 · 项数 · 耗时 · base 指针
- 展开后逐项列出：文件路径 / 方向 / 三路状态 / 耗时 / 错误 / 当前裁决
- 默认回看最近 20 批；`transport-health` 这类行不是批次，不进明细

逐项三路状态（稳定字面量，界面经 `sync.batch.diff.*` 映射）：

| 状态 | 判定 | 可逐项选择 |
|------|------|------------|
| `unchanged` | 两侧一致 | 否 |
| `mine_only` | 仅本地变化 | 否 |
| `theirs_only` | 仅远端变化 | 否 |
| `both_same` | 双改但内容一致（伪冲突） | 否 |
| `both_changed` | **双改**，两侧内容不同 | **是**（三选一） |
| `no_base` | 无 base 指针或缺侧 | 否（置灰） |

比较用内容哈希，不读时间戳。历史批次不迁移、不重写：老 journal 行缺 base 字段即按「无 base」处理，面板会明说该批次只能「保留两者」。

## 双改逐项裁决

- 只有 `both_changed` 的项可以三选一：采用本地侧 / 采用远端侧 / 保留两者
- **默认裁决恒为「保留两者」**：每个清单项的默认值就是 `keep_both`，未知裁决字面量也回落 `keep_both`；不预填覆盖值
- **逐项选择必须是显式动作**：空操作者标识整次拒绝（禁止静默自动裁决）；每次裁决回写裁决 / 操作者 / 时间 / 状态到逐项 journal
- **无 base 不覆盖**：base 不可得时后端**硬拒**「采用本地/远端」（不只是界面置灰），即使绕过界面也不会落地
- **结果不碰工作文件树**：裁决写到 `.novel/resolutions/<批次号>/<相对路径>`，远端副本永非真值
- **单项失败不滚整体**：一次可提交多项，失败项落 `error` 且可原样重试，其余项结果保留
- 逐项 journal（`.novel/sync-item-journal.jsonl`）与传输 journal 物理分文件，避免逐项行污染「本地版本水位」

## 全量提取预算上限

批量提取（章节树入口）在**范围选择阶段**就强制带上限，避免「全量重提烧预算 / 失控排队」：

- 范围两种：仅未提取（默认）/ 全部章节；全量模式默认跳过已有完整快照的章节，勾选「强制重提」才无视跳过
- 预算上限：默认 20 章，硬顶 60 章，**强制开启**（把上限调大不能绕过）；超出即停并记账，界面明示「已触达预算上限 N 章，超限即停并记账」以及超限跳过章数
- **Draft-first**：提取产出只停在草稿（ready）态，必须经 accept 才回填正式记忆，因此批量提取不会静默改写记忆库
- 可随时取消：已完成的章保留，未开始的章不再排队

## 世界规则保护声明

Canon 正史规则（`canonRules`）在上下文预算里享**独立预留槽**，与对话历史、资料页、索引等段分开计算：

- **独立预留**：标准额度 3,840 字符，从总上下文预算中单独切出，不被其他段的涨落挤占
- **零截断**：正史规则**永不因预算被裁剪**——预算不足时宁可挤占其他段，也不删规则。告警记录里的「是否截断」恒为 `false`
- **超限告警（只告警不裁剪）**：规则体量超出预留槽时，生成一条容量告警并**双记**（trace 审计留痕 + journal 可重放流水），界面以横幅说明「已全文保留（未截断），可能挤占其他上下文段」
- **稳定前缀**：规则与技能段、格式契约等不变字段一起进缓存前缀（带版本号 + 哈希），动态内容（资料索引、页面正文、章节草稿）永不进缓存段，因此正史规则既不会被裁掉，也不会让前缀缓存失效

## 状态与限制

- 空态：无批次记录时显示「尚无批次记录（完成一次推送或拉取后出现）」；未配置目标时同步设置区提示先完成目标配置
- 加载 / 错误：操作进行中按钮禁用；失败以红字提示具体原因（含跳过原因），不静默吞错
- 无权限：GitHub 目标需要私有仓写权限与 `nb:github` 凭据；本地文件夹目标无需凭据，改为校验绝对路径与目录可写
- 已知限制：
  - 若本地某版本来自**推送**（本地无同名快照），该冲突批次的本地侧不可得，逐项三选一会降级为「只能保留两者」（不丢数据，但无法逐项覆盖）
  - 批次明细只带批次总耗时，块级耗时记 0（拉取循环尚未逐块计时）
  - GitHub 目标 1 MiB 分界点（contents API ↔ Git Data API）为当前锁定值，阈值调优与 release 附件大文件路径仍在待办
